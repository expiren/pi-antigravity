# Claude request compatibility

The provider validates Claude output caps locally before a request. With thinking
enabled, `maxOutputTokens` must be a positive integer greater than the enabled
thinking budget; an invalid explicit cap is reported to the caller, not silently
raised and not treated as an account quota failure. Host and runtime limits still
bound the final cap. Without an explicit cap, reasoning-enabled Claude Opus 4.6
defaults to at most 8,192 output tokens; Sonnet and reasoning-off requests retain
their existing defaults.

Claude history replay includes a thinking block only when it carries its original
signature. Unsigned historical thinking is omitted, while signed thinking and
visible assistant text remain. This avoids submitting an invalid replay payload
without changing the recorded transcript.

The host's automatic session-title request is generated by Senpi, not this
provider. Its separate internal token cap and any binary/runtime patch needed
for reasoning-required title models are deliberately excluded from this
repository and its upstream pull request.

Run `bun --preload ./scripts/v3-offline.ts scripts/test-claude-thinking.ts` and
`bun --preload ./scripts/v3-offline.ts scripts/test-transcript-context.ts` to
check request construction, terminal HTTP 400 behavior, and signature replay
without live provider traffic.
